# 🕷️ Enterprise Async Web Scraper & Catalog Extractor

> Промышленное асинхронное ядро для сбора данных с динамических каталогов, маркетплейсов и защищённых e-commerce платформ на базе Python.

Проект построен по архитектуре **«Core Engine / Custom Target Adapter»**: ядро берёт на себя всю инфраструктурную сложность — управление браузерным пулом, маскировку отпечатков, фильтрацию трафика, неблокирующее хранение в БД и генерацию Excel-отчётов, — а правила разбора конкретной площадки подключаются отдельным, независимо сменяемым классом-адаптером.

---

## ⚡ Ключевые инженерные особенности

### 1. Асинхронное ядро и контроль нагрузки (`asyncio` + `Semaphore`)
Все страницы каталога обрабатываются конкурентно в рамках одного процесса Chromium через `asyncio.gather`. Жёсткий лимит параллелизма задаётся через `asyncio.Semaphore(N)` — это защищает от взрывного потребления ОЗУ и от срабатывания Rate-Limit на стороне сервера. Скорость сбора линейно масштабируется параметром `--concurrency`.

### 2. Строгая валидация и санитизация данных (`Pydantic v2`)
Никаких сырых словарей. Каждая карточка товара проходит через строгую схему `ProductItem`:
- **`parse_price`** — вырезает валютные символы, пробелы, нормализует разделитель `,` → `.`, приводит к `float`.
- **`clean_title`** — схлопывает множественные пробелы/переносы, отклоняет пустые строки.
- **`validate_url`** — проверяет наличие схемы `http://` / `https://`.

Ошибки валидации перехватываются на уровне адаптера — невалидная карточка логируется и пропускается, не роняя весь процесс.

### 3. Stealth-режим и эмуляция пользователя (Playwright)
- **Сокрытие маркеров автоматизации:** через `add_init_script` перезаписываются `navigator.webdriver` и `window.chrome` — стандартные fingerprint-детекторы не видят Chromium в режиме автоматизации.
- **Реалистичный User-Agent, Viewport, Locale, Timezone:** контекст браузера создаётся с параметрами типичного российского пользователя Chrome.
- **Human Scroll:** перед парсингом DOM выполняется плавный имитационный скролл (`mouse.wheel`) с рандомизированными дельтами (350–650 px) и случайными задержками (0.3–0.6 с) для корректной инициализации `Lazy-Load` блоков.
- **Случайные паузы между запросами:** 0.8–2.0 сек после обработки каждой страницы.

### 4. Перехват и фильтрация медиа-трафика (`Route Interception`)
Асинхронный перехватчик на уровне сетевого стека браузера блокирует загрузку ресурсов типов `image`, `media`, `font`, `stylesheet`. Это:
- **ускоряет** сбор данных в 3–5 раз (DOM-контент загружается без ожидания тяжёлых ресурсов),
- **экономит** трафик прокси-серверов в разы,
- **снижает** нагрузку на память процесса Chromium.

Набор блокируемых типов вынесен в константу `_BLOCKED_RESOURCE_TYPES` для удобного конфигурирования.

### 5. Отказоустойчивое хранилище (`sqlite3` + `asyncio.to_thread`)
- Используется **стандартная библиотека** `sqlite3` — ноль дополнительных зависимостей.
- Все блокирующие вызовы (`connect`, `execute`, `commit`) выполняются в пуле потоков через `asyncio.to_thread`, не блокируя event loop.
- Защита от дублей: `INSERT OR IGNORE` по первичному ключу `sku`.
- Метод `save_items` возвращает количество **новых** записей, добавленных в рамках текущей сессии.

### 6. Ротация прокси (`ProxyManager`)
- Циклический балансировщик HTTP/SOCKS5 прокси через `itertools.cycle`.
- Поддержка авторизации (`login:password@host:port`), причём парсинг URL реализован через `rsplit('@', 1)` — устойчив к символу `@` в теле пароля.
- Загрузка пула из текстового файла (один прокси на строку, строки `#...` игнорируются).

### 7. Генерация бизнес-отчётов (`OpenPyXL`)
- Корпоративная шапка с синим фоном (`#1F497D`) и белым жирным шрифтом.
- Границы всех ячеек, финансовый формат цен (`#,##0.00`).
- Автоподбор ширины столбцов с ограничением [12, 50] символов.
- Обработка `OSError` при сохранении — ошибка логируется, процесс не падает.

## 🚀 Быстрая установка

### Требования
- Python **3.10+**
- pip / venv

### Шаг 1 — Создать виртуальное окружение
```bash
python -m venv .venv

# Windows
.venv\Scripts\activate

# Linux / macOS
source .venv/bin/activate
```

### Шаг 2 — Установить зависимости
```bash
pip install -r requirements.txt
```

### Шаг 3 — Установить браузер Playwright
```bash
playwright install chromium
```

### Шаг 4 — Запустить демо-сессию
```bash
python main.py --pages 5 --concurrency 3
```

## 🖥️ CLI-аргументы командной строки

| Аргумент | Тип | По умолчанию | Описание |
|---|---|---|---|
| `--pages` | `int` | `3` | Количество страниц каталога для обхода |
| `--concurrency` | `int` | `3` | Максимальное число одновременно открытых вкладок браузера |
| `--output` | `str` | `demo_catalog.xlsx` | Имя выходного Excel-файла (относительный или абсолютный путь) |
| `--db` | `str` | `scraped_data.db` | Путь к файлу SQLite. Передайте пустую строку `""` для отключения БД |
| `--proxies` | `str` | `None` | Путь к `.txt`-файлу со списком прокси (один на строку) |
| `--headful` | flag | `False` | Запустить с видимым окном браузера (удобно для отладки) |

### Примеры запуска

**Базовый запуск — 10 страниц, 5 параллельных вкладок:**
```bash
python main.py --pages 10 --concurrency 5
```

**Полный боевой запуск с прокси и кастомными путями:**
```bash
python main.py --pages 50 --concurrency 8 --output report_2024-10.xlsx --db data/products.db --proxies proxies.txt
```

**Отладка в видимом браузере:**
```bash
python main.py --pages 2 --concurrency 1 --headful
```

**Только сбор данных без записи в БД:**
```bash
python main.py --pages 20 --db ""
```

**Указать абсолютный путь для Excel-файла:**
```bash
python main.py --pages 10 --output "D:\Reports\catalog_$(date +%Y%m%d).xlsx"
```

## 🔧 Формат файла прокси (`proxies.txt`)

Один прокси на строку. Строки, начинающиеся с `#`, игнорируются.

```text
# HTTP прокси (без авторизации)
http://192.168.1.100:8080

# SOCKS5 с авторизацией (поддерживается @ в пароле)
socks5://user:p@ssw0rd@proxy.example.com:1080

# HTTP с авторизацией
http://admin:secret@10.0.0.5:3128
```

## 🔒 Коммерческая адаптация и разработка под заказ

> **Важно:** В публичном репозитории представлен **демонстрационный адаптер** `DemoBooksAdapter`, настроенный на открытый тестовый стенд [books.toscrape.com](https://books.toscrape.com) — для верификации работоспособности ядра.

### Как написать адаптер под свою площадку

Достаточно унаследовать `BaseCatalogAdapter` и реализовать три метода:

```python
class MyShopAdapter(BaseCatalogAdapter):

    @property
    def target_name(self) -> str:
        return "MyShop_Production"

    async def build_catalog_url(self, page_number: int) -> str:
        # Формирует URL страницы пагинации
        return f"https://myshop.ru/catalog?page={page_number}"

    async def extract_items(self, page: Page) -> List[ProductItem]:
        items = []
        # Здесь — вся логика разбора DOM конкретного сайта
        for card in await page.query_selector_all(".product-card"):
            ...
            items.append(ProductItem(sku=..., title=..., price=..., url=...))
        return items
```

После этого передайте экземпляр адаптера в `ScrapingEngine`:
```python
engine = ScrapingEngine(adapter=MyShopAdapter(), ...)
```

### Типовые коммерческие сценарии

Боевые адаптеры разрабатываются индивидуально под задачу заказчика и включают:

| Сценарий | Что реализуется |
|---|---|
| **B2B-каталоги (1C, SAP-выгрузки)** | Парсинг табличного HTML, сопоставление кодов номенклатуры |
| **Маркетплейсы под Cloudflare / DataDome** | Обход антибот-систем, управление fingerprint-профилем |
| **Авторизация и сессии** | Воспроизведение flow входа, работа с cookies / JWT |
| **Перехват внутренних JSON API** | `page.on("response", ...)` — перехват XHR/Fetch без CSS-селекторов |
| **Интеграция с внешними системами** | Экспорт в PostgreSQL, ClickHouse, S3, 1C, CRM через API |
| **Распределённый режим** | Масштабирование на несколько машин через очередь задач (RabbitMQ / Redis) |
